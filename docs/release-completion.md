## Architecture

React -> centralized API client -> FastAPI validation -> saved feature/preprocessing/model pipeline -> classification -> transactional SQLite snapshot -> connected workspace views and saved report exports.

Historical replay enters the same inference service. Training/evaluation stay offline. Model Lab remains optional. Missing models produce errors instead of invented results.

## Scope and data truth

- Replay excerpts come from the existing verified UNSW-NB15 official holdout (2015). The manifest records source hashes, row IDs, source URL, and excerpt hashes. These are real benchmark features, not a newer dataset.
- Replay classifications are generated by the loaded model. Ground-truth source labels are not model inputs and are not promised to match predictions.
- Playback follows record order at a chosen demonstration rate; original timestamps and device relationships do not exist in those excerpts.
- Optional IP/time fields add context only. They do not make an incompatible feature schema compatible. Topology is limited to 40 devices and 80 directed connections for readable rendering; the full records table remains available.
- Raw uploaded bytes and ignored extra columns are not retained. Validated feature rows, optional recognized context and prediction snapshots are stored in the local database. Delete through Saved analyses to remove them. SQLite is local storage, not encrypted storage; use this local single-user app accordingly.
- The held-out false-positive rate remains 16.58%. This is an academic analysis aid, not an unattended incident detector. No new training or threshold tuning against the test set occurred.

## Try it

1. Start the API and Vite using [local setup](phase-1.md).
2. Open Network Pulse; choose a historical scenario and click **Analyze historical replay**.
3. Use playback controls; open Command Center or Threat Investigation to see the same saved result.
4. Open Reports and download CSV/PDF.
5. Refresh, reopen the result through Saved analyses, or delete it.

For uploaded context, supported aliases are `source_ip`/`src_ip`/`srcip`, `destination_ip`/`dst_ip`/`dstip`, and `timestamp`/`start_time`. IPs must be valid IPv4/IPv6; timestamps require timezone-aware ISO 8601. Existing 5 MiB and 10,000-row limits remain.

No live packet capture, user accounts, newer dataset adapters, or cross-network model guarantees were added.
